InduSense - Datasets Used
=========================

Project:
Multimodal Maintenance Intelligence Agent for Industrial Troubleshooting

The datasets are used for different parts of the system. They are not forced
into one model.

1. AI4I 2020 Predictive Maintenance Dataset
   Local data:
   data/ai4i+2020+predictive+maintenance+dataset/ai4i2020.csv

   Used for:
   - Industrial machine-failure prediction
   - Sensor-based predictive maintenance
   - Heat Dissipation Failure (HDF), Power Failure (PWF), Tool Wear Failure
     (TWF), and Overstrain Failure (OSF)

   Main inputs:
   Air temperature, process temperature, rotational speed, torque, and tool
   wear.

   InduSense output:
   Predicted fault, condition probability (Pc), sensor contribution, and
   recommended inspection.

2. NASA C-MAPSS Turbofan Engine Dataset
   Local/project reference:
   NASA C-MAPSS / CMAPSSData.zip

   Used for:
   - Turbofan engine degradation
   - Remaining Useful Life (RUL) prediction
   - Engine health trend analysis

   InduSense output:
   Estimated RUL, RUL interval, degradation condition, and engineering
   escalation when supporting manual evidence is unavailable.

3. FEMTO / PRONOSTIA Bearing Dataset
   Local/project reference:
   Datasets/Bearing/

   Used for:
   - Bearing degradation analysis
   - Vibration-based fault classification
   - Spectral feature analysis

   Main features:
   Vibration, kurtosis, crest factor, FFT peak, and envelope-spectrum
   indicators.

   InduSense output:
   Bearing fault condition, confidence score, spectral indicators, and
   maintenance evidence.

4. Paderborn Bearing Dataset
   Used for:
   - Additional bearing-fault validation
   - Physical bearing leave-out evaluation
   - Testing generalization of the bearing classifier

   InduSense output:
   Bearing health classification and vibration-based evidence.

5. Factory Sensors Failure Labels Dataset
   Local data:
   Datasets/factory-sensors-failure-labels (1)/

   Used for:
   - Industrial sensor-failure labels
   - Supporting fault-detection experiments
   - Testing sensor-to-condition mappings

6. Condition Monitoring of Hydraulic Systems Dataset
   Local data:
   Datasets/condition+monitoring+of+hydraulic+systems/

   Used for:
   - Hydraulic-system condition monitoring
   - Pressure and sensor-based fault analysis
   - Testing hydraulic equipment diagnostics

7. Synthetic Maintenance Manuals Corpus
   Local project data:
   documents/
   server/documents/

   Used for:
   - Technical-document retrieval
   - Evidence passages for case diagnosis
   - Citation-backed troubleshooting explanations
   - Condition-Evidence Alignment (CEA)
   - Distractor and semantic-proximity conflict detection

   InduSense output:
   Retrieved passage, document, page number, bounding-box metadata, citation,
   alignment verdict, and evidence confidence.

8. DocLayNet
   Source:
   https://github.com/DS4SD/DocLayNet

   Used for:
   - Document-layout understanding
   - Detecting text, titles, paragraphs, tables, figures, captions, and lists

9. TableBank
   Source:
   https://github.com/doc-analysis/TableBank

   Used for:
   - Table detection
   - Table structure extraction
   - Error-code tables, specification tables, and troubleshooting grids

10. FUNSD
    Used for:
    - Noisy scanned-document understanding
    - OCR and form/key-value extraction
    - Text-region and entity relationships

11. PubLayNet
    Used for:
    - Document-layout analysis
    - Supporting layout recognition for technical documents

12. SROIE
    Used for:
    - OCR and document information extraction
    - Testing extraction from scanned documents and structured forms

13. IIIT5K-Words
    Used for:
    - OCR text-recognition experiments
    - Word-level recognition evaluation

Dataset-to-System Mapping
=========================

AI4I 2020                  -> Fault prediction and sensor reasoning
NASA C-MAPSS               -> Turbofan degradation and RUL prediction
FEMTO / PRONOSTIA          -> Bearing vibration and degradation analysis
Paderborn Bearing          -> Bearing classifier validation
Factory Sensors            -> Industrial sensor-failure experiments
Hydraulic Systems          -> Hydraulic condition monitoring
Maintenance Manuals        -> Retrieval, citations, and troubleshooting
DocLayNet / PubLayNet      -> Document-layout understanding
TableBank                  -> Table detection and extraction
FUNSD / SROIE / IIIT5K     -> OCR and scanned-document understanding

Important Note
==============

AI4I 2020, NASA C-MAPSS, and bearing datasets are used for predictive
maintenance demonstrations. The document-understanding datasets support the
OCR, layout, and table-processing components. A dataset is only used for the
task it is appropriate for.

Recommended modeling split
---------------------------

- AI4I: stratified train/validation/test split, preserving rare failure labels.
- Factory sensors: chronological, asset-aware split to avoid leakage from
  adjacent hourly readings and repaired assets.
- Hydraulic system: cycle-aware split; keep profile labels aligned with each
  60-second cycle.
- Bearing: bearing-ID or operating-condition leave-one-group-out split;
  never randomly split overlapping windows from the same recording across
  train and test.

Data-quality risks to address
-----------------------------

- Severe class imbalance exists in AI4I and factory failure labels.
- Random row splits can leak temporal or asset identity information.
- Hydraulic files have multiple sampling rates and very high dimensionality.
- Bearing archives are mixed between compressed RAR and extracted MAT files.
- The project currently references NASA C-MAPSS, but it is not present in the
  analyzed folder.
- Document-understanding datasets are not locally available in this folder, so
  OCR/layout/table model training cannot be verified from this inventory alone.
