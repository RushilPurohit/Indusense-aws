1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
InduSense re-architects industrial maintenance into a single connected pipeline:
    PREDICT -> RETRIEVE -> ALIGN -> VALIDATE -> ADAPT -> EXPLAIN

Every screen is a view onto ONE shared object: the DIAGNOSIS CASE.
The system connects physical sensor telemetry (AI4I 2020, Factory Sensors,
UCI Hydraulic Rig, Paderborn Bearing Datacenter) with technical manuals and
knowledge graphs, specifically detecting and blocking "Semantic Proximity Fallacies"
(when naive RAG retrieves text with matching words like "air delta" or "pressure"
that target the wrong physical machine subsystem).

InduSense is configured to run out-of-the-box with ZERO AWS credentials:
- Local disk storage adapter (mocking S3)
- Local layout & PyPDF parser (mocking AWS Textract)
- Local Scikit-Learn/XGBoost predictor (mocking SageMaker)
- In-memory dense cosine vector & graph index (mocking OpenSearch)
- Local template explanation synthesizer (mocking Bedrock)
- Deterministic rule router (mocking AWS Lambda)
- Frontend fallback mock adapter if backend is ever paused

9. TROUBLESHOOTING
--------------------------------------------------------------------------------
Q: PowerShell shows error "ModuleNotFoundError: No module named 'server'"?
A: You are in `backend\app`. Run `cd ..\..` to return to `abb-maintenance-intelligence`, then run:
   python -m uvicorn server.main:app --host 127.0.0.1 --port 8000 --reload

Q: PowerShell shows error "npm.ps1 cannot be loaded because running scripts is disabled"?
A: Execute npm using 'npm.cmd' instead:
   npm.cmd run dev

Q: Backend shows warnings about Qdrant or Neo4j?
A: This is normal in local mode. InduSense uses in-memory and SQLite fallback adapters with
   zero Docker dependencies.
